# 项目约束(CONSTRAINTS)

## 范围红线

- 禁止实现或引入团队协作、共享清单、评论及权限角色功能。[§2.3]
- 禁止实现或引入第三方日历双向同步。[§2.3]
- 禁止实现或引入复杂项目管理、甘特图及工时计费功能。[§2.3]
- 禁止选定、集成或实现具体身份认证供应商；同步功能只能依赖已有的稳定账户标识和会话能力。[§2.3]

## 任务与日期

- 每条任务必须包含非空标题、稳定唯一 ID、创建时间和更新时间。[§4.1]
- MVP 创建流程必须要求截止日期；截止日期必须保存年、月、日。[§4.1][§5 B7]
- 起始时间和结束时间必须为可选字段，并按用户本地时区解释和展示。[§4.1][§5 B1]
- 同时存在起始时间和结束时间时，结束时间不得早于起始时间；违反时必须拒绝保存、保留用户输入并指出修正动作。[§4.1][§5 B3][§6 U3]
- 夏令时导致日期时间无效时必须拒绝静默处理并提示用户修正。[§5 B1]
- 自然语言日期解析结果必须在保存前可见且可编辑。[§4.1]
- 自然语言解析失败时必须回退到日期和时间选择器，禁止猜测日期或静默保存。[§4.1][§5 B2]
- 日期为空的任务必须排除在今日、未来和逾期视图之外，直至补充日期。[§5 B7]
- 删除任务必须提供明确确认或可撤销机制。[§4.1]

## 状态机边界

- 任务完成状态只允许执行“未完成→已完成”和“已完成→未完成”；未列出的完成状态转移一律拒绝。[§4.2]
- “未完成→已完成”必须记录完成时间，“已完成→未完成”必须清除当前完成时间。[§4.2]
- 完成重复任务时，当前实例必须保持已完成，并且只生成一个继承标题、属性和重复规则的下一期未完成实例。[§4.2]
- 重复触发完成操作不得生成重复实例。[§4.2]
- 父任务存在未完成子任务时，禁止静默覆盖父任务完成状态。[§4.4]
- 已完成任务不得继续触发未完成提醒。[§4.5]
- 完成任务后必须立即将其移出逾期集合。[§5 B4]

## 重复规则

- 重复周期必须支持每日、每周、每月和自定义；每周必须支持指定星期，自定义必须至少包含间隔数值和周期单位。[§4.2]
- 月度重复遇到目标月份不存在原日期时必须使用该月最后一天，后续月份必须继续按原始日期锚点计算。[§4.2][§5 B5]
- 禁止在跨月调整中覆盖重复任务的原始日期锚点。[§5 B5]
- 重复规则必须使用结构化字段保存，禁止仅依赖展示文本。[§7 D2]
- 重复实例必须保存来源任务 ID 或来源规则 ID。[§7 D2]

## 视图与筛选

- 必须提供今日待办、未来任务、逾期任务、已完成和日历五种视图。[§4.3]
- 今日视图必须按用户本地日期筛选。[§4.3]
- 未来视图只能包含截止日期晚于今天的未完成任务。[§4.3]
- 已完成视图必须按完成时间筛选。[§4.3]
- 逾期只能定义为“未完成且当前时间晚于任务结束时间”；无具体时间时必须以本地截止日期结束时刻判断。[§4.3]
- 逾期任务必须红色高亮并按截止时间升序排在非逾期任务之前。[§4.3][§5 B4]
- 逾期状态禁止仅用颜色表达，必须同时提供文本或图标语义。[§6 U4]
- 日历视图必须按截止日期展示任务，并允许从日期单元格进入任务详情或创建任务。[§4.3]
- 筛选、切换视图和完成任务不得修改任务的原始日期或重复规则。[§4.3]

## 组织属性、提醒与统计

- 组织属性必须为可选项，禁止其阻塞两步以内的基础任务创建。[§4.4]
- 删除清单时必须明确指定任务保留策略，禁止在未确定保留策略时执行删除。[§4.4]
- 任务必须支持多个标签，并支持按标签筛选及移除标签。[§4.4]
- 优先级必须至少提供四级，并支持稳定排序和筛选。[§4.4]
- 有具体时间的任务必须默认以结束时间提醒，无具体时间的任务必须默认以截止日当地 09:00 提醒。[§4.5]
- 提醒失败或通知权限被拒绝时，必须在应用内显示待处理状态。[§4.5]
- 完成率必须按“已完成任务实例数÷应完成任务实例数”计算，取消项不得计入分母。[§4.5]
- 完成热力图必须按用户本地日期聚合，重复任务必须按实际生成的任务实例计数。[§4.5]

## 本地优先与同步

- 任务保存和状态切换必须立即写入并反映在当前设备，云端同步必须异步进入同步队列。[§4.6]
- 云端不可用时仍必须允许本地创建、编辑、完成和查看任务，禁止因网络不可用阻塞这些操作。[§5 B6]
- 同步失败时必须保留本地变更、显示稍后重试提示，并支持手动或自动重试。[§4.6]
- 同步重试不得产生重复任务。[§4.6]
- 同一账户的任务增删改、完成状态、重复规则和组织属性必须在多设备间最终一致。[§4.6]
- 同一记录冲突时必须使用服务器可比较的更新时间和稳定设备标识进行确定性处理，所有设备必须得到一致结果。[§4.6]
- 同步队列和错误状态必须可诊断，网络恢复后必须继续处理未同步变更。[§4.6]

## 数据与接口

- Task 必须至少包含 `id`、`title`、`dueDate`、`startAt`、`endAt`、`timezone`、`status`、`completedAt`、`recurrence`、`listId`、`tags`、`priority`、`parentId`、`createdAt`、`updatedAt`。[§7 D1]
- 完成时间、更新时间和同步时间必须使用可比较的标准时间格式保存，展示时必须转换为用户时区。[§7 D3]
- 日期解析器必须返回结构化日期、时间、重复信息和解析状态。[§7 D4]
- 日期解析器必须让调用方可区分成功、部分成功和失败三种解析结果。[§7 D4]

## 交互与非功能红线

- 从任一主要任务列表打开快速创建并保存，主要交互不得超过两步。[§6 U1]
- 日期解析确认必须以内联控件完成。[§6 U1]
- 完成、取消完成和切换视图必须支持单次点击或等价键盘操作。[§6 U2]
- 错误提示必须指出具体字段和修正动作，禁止仅显示通用失败信息。[§6 U3]
- 移动端和桌面端均必须支持键盘操作，且界面元素不得遮挡任务内容。[§6 U5]
- 同步、提醒调度和完成反馈不得阻塞主交互。[§4.2][§8 N1]
- 核心领域逻辑必须能在无网络环境下运行和测试。[§8 N2]
- 数据传输和云端存储必须使用平台认可的加密机制。[§8 N3]
- 日志禁止记录任务标题等敏感内容。[§8 N3]
- 删除、重复生成和同步重试操作必须具备幂等性。[§8 N4]

## 发布门禁

- MVP 发布必须覆盖 F1、F2、F3 以及 B1-B7 中与其相关的规则。[§9 A1]
- F4、F5、F6 未全部完成前，禁止宣称已覆盖完整的规划、执行、提醒、统计和多端同步闭环。[§9 A2]
- 每个功能特性都必须包含自动化领域测试。[§9 A3]
- 首个实现特性必须同时建立可重复运行的测试命令。[§9 A3]
