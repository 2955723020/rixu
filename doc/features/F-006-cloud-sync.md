# F-006 — 本地优先的多端云端同步

在任务、完成、重复和组织数据之上建立本地优先同步层。所有写操作先提交本地存储并进入幂等同步队列，再异步上传云端。相同账户的多个设备最终收敛到一致数据；同步失败时保留本地结果并展示稍后重试状态。对同一记录的并发修改使用服务器可比较的更新时间和稳定设备标识执行确定性冲突处理，避免重复任务和不一致状态。

## Acceptance criteria

- [ ] 创建、编辑、删除和完成操作在当前设备立即可见，即使网络不可用也能继续使用。
- [ ] 网络恢复后，待同步队列能自动或手动重试，并在成功后清除对应待处理状态。
- [ ] 同一账户的两台设备完成同步后，任务字段、完成状态、重复规则和组织属性最终一致。
- [ ] 同步失败保留本地变更并显示可操作的稍后重试提示；重复重试不会创建重复任务。
- [ ] 同一记录发生冲突时，按更新时间和稳定设备标识得到唯一结果，所有设备最终显示相同结果。
- [ ] 同步日志可区分待同步、成功和失败状态，且不记录任务标题等敏感内容。

## Test cases

- [ ] TC-SYNC-1: 断网时创建并完成任务，断言本地立即可读且同步队列保留待处理记录。 (来源: §4.6-F6；§5-B6)
- [ ] TC-SYNC-2: 模拟网络恢复并重试队列，断言变更上传成功且重复重试不产生重复任务。 (来源: §4.6-F6；§8-N4)
- [ ] TC-SYNC-3: 在两个设备副本上修改同一任务，执行冲突解决后断言结果确定且两端最终一致。 (来源: §4.6-F6)
- [ ] TC-SYNC-4: 模拟同步失败，断言本地变更不丢失、界面显示重试状态且日志不含任务标题。 (来源: §4.6-F6；§8-N3)
