# F-001 — 任务生命周期与日期输入

在当前仅有文档的仓库中建立首个可运行的任务领域模型和测试基础。实现任务的创建、读取、更新、删除，本地持久化所需的稳定字段，以及截止日期、可选起始时间和结束时间的结构化保存。所有时间按用户本地时区解释；结束时间早于起始时间时拒绝保存并返回字段级错误。提供中文自然语言日期解析接口，至少覆盖“明天下午3点”等相对日期加时间表达；解析失败或部分失败时返回明确状态，让界面转入手动日期/时间选择，而不是猜测保存。该特性是后续完成、视图、组织和同步功能的数据基础。

## Acceptance criteria

- [ ] 创建任务后可通过唯一 ID 读取，并保留标题、截止日期、起始时间、结束时间、时区、状态及审计时间字段。
- [ ] 更新任务会修改业务字段和 updatedAt；删除任务不会影响其他任务，并提供可验证的确认或撤销边界。
- [ ] 结束时间早于起始时间时保存操作失败，返回可定位到时间字段的错误，且原输入仍可被修正。
- [ ] 自然语言输入“明天下午3点”在给定时区和当前时间下解析为确定的下一日 15:00；解析结果可被调用方读取和编辑。
- [ ] 无法识别的自然语言日期返回失败状态并触发手动日期和时间输入路径，不生成默认日期。
- [ ] 日期和时间的存储、比较及展示遵循用户本地时区，跨时区转换不会改变任务的绝对时刻。

## Test cases

- [ ] TC-TASK-1: 创建并读取带截止日期和起止时间的任务，字段值和唯一 ID 保持一致。 (来源: §4.1-F1)
- [ ] TC-TASK-2: 提交结束时间早于起始时间的任务，断言保存被拒绝且返回字段错误。 (来源: §4.1-F1；§5-B3)
- [ ] TC-TASK-3: 在固定当前时间和时区下解析“明天下午3点”，断言日期为下一日且时间为 15:00。 (来源: §4.1-F1)
- [ ] TC-TASK-4: 输入无法识别的自然语言日期，断言返回失败状态且不产生猜测日期。 (来源: §4.1-F1；§5-B2)
