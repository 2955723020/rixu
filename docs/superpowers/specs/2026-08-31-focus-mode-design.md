# 日序专注模式设计方案

> 版本：v1 · 状态：待实施 · 日期：2026-08-31
> 范围：为现有日序 Web 前端增加番茄钟、自由计时、沉浸式专注体验和独立专注统计。

## 1. 目标与范围

专注模式帮助用户从任务规划进入实际执行，并记录投入时间。它支持两种方式：

- 番茄钟：按预设时长倒计时，默认专注 25 分钟、休息 5 分钟。
- 自由计时：从零开始正向计时，由用户决定何时结束。

专注可以关联现有任务，也可以使用不创建任务的临时主题。专注结束只记录时长，不自动完成或修改关联任务。

本期不包含系统通知、跨设备同步、白噪音、连续自动番茄、严格网站拦截或任务工时计费。

## 2. 产品决策

- 番茄钟与自由计时同时提供。
- 专注结束后仅保存专注记录，不改变任务完成状态。
- 用户提前结束时保留实际时长，结果标记为“提前结束”。
- 专注主体验采用沉浸式全屏，隐藏常规侧栏和任务列表。
- 刷新或重新打开应用后，活动会话恢复为暂停状态，关闭期间不计时。
- 番茄钟完成后手动开始休息，不自动切换。
- 专注可不关联任务；无任务专注使用临时主题，且不会创建新任务。
- 番茄钟默认 25/5 分钟，开始前可调整并记住上次设置。
- 计时结束使用页面提示和短提示音，不申请浏览器系统通知权限。
- 专注统计使用独立页面，不混入现有任务完成率和完成热力图。

## 3. 架构

专注功能作为独立前端模块实现，不修改根目录 `src/` 与 `tests/` 的任务领域模型。

```text
web/src/focus/
├── focus-machine.js       纯计时状态机和时长计算
├── focus-selectors.js     今日、本周、七天和主题分布统计
├── focus-store.js         Zustand persist，key: rixu-focus:v1
├── focus-audio.js         完成提示音，失败时静默降级
├── FocusSetupDialog.jsx   开始前模式、主题和时长配置
├── FocusSession.jsx       沉浸式专注与休息界面
├── FocusMiniBar.jsx       退出沉浸模式后的固定计时条
└── FocusStatsPage.jsx     独立专注统计页
```

现有任务 Store 继续只负责任务与清单。专注 Store 通过 `taskId` 可选关联任务，并保存 `subjectSnapshot`，不持有或修改任务对象。

数据流：

```text
任务行 / 顶栏入口
        ↓
FocusSetupDialog
        ↓ startSession
Focus Store ── persist ── localStorage: rixu-focus:v1
        ↓
FocusSession / FocusMiniBar
        ↓ finishSession
历史 records[] ── selectors ── FocusStatsPage
```

## 4. 数据模型

### 4.1 用户设置

```js
{
  focusMinutes: 25,
  breakMinutes: 5,
  lastMode: 'pomodoro'
}
```

`focusMinutes` 限制为 1 至 180，`breakMinutes` 限制为 1 至 60。保存成功开始专注时更新设置；仅在弹窗中输入但取消时不更新。

### 4.2 活动会话

```js
{
  id: 'uuid',
  mode: 'pomodoro' | 'stopwatch',
  phase: 'focus' | 'break',
  status: 'running' | 'paused' | 'focus-complete' | 'break-complete',
  taskId: null | 'task-id',
  subjectSnapshot: '评审方案',
  startedAt: '2026-08-31T08:00:00.000Z',
  resumedAt: '2026-08-31T08:05:00.000Z' | null,
  accumulatedMs: 300000,
  targetMs: 1500000 | null,
  breakTargetMs: 300000,
  recordId: null | 'record-id'
}
```

`recordId` 用于保证番茄到点或重复事件只生成一条专注历史。自由计时的 `targetMs` 为 `null`。休息沿用同一个活动会话，但不会生成专注历史。

### 4.3 历史记录

```js
{
  id: 'uuid',
  sessionId: 'uuid',
  taskId: null | 'task-id',
  subjectSnapshot: '评审方案',
  mode: 'pomodoro' | 'stopwatch',
  startedAt: '2026-08-31T08:00:00.000Z',
  endedAt: '2026-08-31T08:25:00.000Z',
  focusedMs: 1500000,
  outcome: 'completed' | 'stopped-early'
}
```

记录保存标题快照，因此任务改名或删除后历史仍可理解。删除任务不级联删除专注历史，也不中断正在进行的专注。

### 4.4 持久化状态

```js
{
  settings,
  activeSession,
  records
}
```

统一持久化到 `rixu-focus:v1`。首版不设置历史数量上限；统计计算保持纯函数，后续可在数据量成为实际问题时增加归档策略。

## 5. 计时状态机

### 5.1 状态转换

```text
idle
  ├─ start pomodoro ─→ focus/running
  └─ start stopwatch → focus/running

focus/running ←→ focus/paused
focus/running ── 到点 ─→ focus-complete
focus/running|paused ── 提前结束并确认 ─→ idle
focus-complete ── 开始休息 ─→ break/running
focus-complete ── 返回任务 ─→ idle

break/running ←→ break/paused
break/running ── 到点 ─→ break-complete
break/running|paused ── 跳过 ─→ idle
break-complete ── 返回任务 ─→ idle
```

同一时间只允许一个活动会话。存在活动会话时再次点击任何开始入口，不创建新会话，而是打开当前专注界面。

### 5.2 时间计算

运行时实际经过时间为：

```js
elapsedMs = accumulatedMs + (now - resumedAt)
```

暂停时把 `now - resumedAt` 合并进 `accumulatedMs`，然后将 `resumedAt` 设为 `null`。显示层可每秒刷新，但状态机不通过 `setInterval` 累加秒数，避免浏览器后台节流造成漂移。

番茄钟剩余时间为 `max(0, targetMs - elapsedMs)`。达到目标后，实际专注记录按 `targetMs` 保存，避免延迟触发把后台多出的时间计入完成番茄。自由计时与提前结束按实际 `elapsedMs` 保存。

### 5.3 刷新与页面关闭

- `pagehide` 和 `visibilitychange` 进入隐藏状态时，把当前运行区间结算进 `accumulatedMs` 并持久化。
- 应用初始化若发现 `status: running`，立即规范化为 `paused`，保留已结算时长并清空 `resumedAt`。
- 页面关闭到重新打开之间的时间不计入专注或休息。
- 如果页面在番茄达到目标后才触发隐藏结算，则按目标时长生成完成记录，并恢复为 `focus-complete`，不会降为暂停。

### 5.4 完成与幂等

番茄到点时先检查 `recordId`。若为空，创建记录并回写其 ID；若已存在，只恢复完成界面。该顺序通过一次 Store 状态更新完成，避免多个定时事件生成重复记录。

自由计时只有用户主动结束时生成记录，结果为 `stopped-early`。番茄在到点前结束也使用 `stopped-early`；正常到点使用 `completed`。

## 6. 入口与常规界面

### 6.1 顶栏入口

顶栏增加带计时器图标的“开始专注”按钮。点击后打开设置弹窗，默认不关联任务。若已有活动会话，则打开该会话。

### 6.2 任务入口

每个顶层任务行增加“专注此任务”图标按钮，与完成和编辑操作相互独立。点击后打开设置弹窗，并预填 `taskId` 和任务标题快照。已完成任务仍允许关联专注，专注行为不会修改其状态。

### 6.3 侧栏入口

侧栏主导航新增“专注统计”。该入口打开独立 `FocusStatsPage`。存在活动会话时，页面顶部仍显示迷你计时条。

### 6.4 开始设置弹窗

弹窗使用分段控件选择“番茄钟 / 自由计时”。内容包括：

- 可选任务选择器。
- 临时主题输入；关联任务时默认使用任务标题，用户可覆盖本次显示主题但不修改任务。
- 番茄模式下显示专注分钟和休息分钟步进控件。
- 自由计时模式隐藏时长设置。
- 主命令“开始专注”。

主题规则：有关联任务时主题可为空并回退到任务标题；无关联任务时必须输入非空临时主题。错误在字段旁显示，不关闭弹窗。

## 7. 沉浸式专注界面

专注开始后使用覆盖整个应用视口的独立界面，隐藏侧栏、顶栏和任务列表。视觉保持日序的绿、白、中性灰体系，但降低信息密度与装饰。

中央内容：

- 当前主题与可选的关联任务标识。
- 番茄钟显示大号剩余时间与环形进度。
- 自由计时显示大号累计时间，不显示伪进度环。
- 明确的状态文字：专注中、已暂停、本轮完成、休息中、休息结束。

底部控制：

- 运行时：暂停、提前结束、退出沉浸模式。
- 暂停时：继续、提前结束、退出沉浸模式。
- 专注完成：开始休息、返回任务。
- 休息运行或暂停：暂停/继续、跳过休息、退出沉浸模式。
- 休息完成：返回任务。

“提前结束”需要二次确认，并明确显示将保存的实际时长。“退出沉浸模式”只关闭覆盖层，不暂停或结束会话。

键盘操作：

- 空格：在运行和暂停间切换；输入控件获得焦点时不拦截。
- `Escape`：退出沉浸界面；确认弹窗打开时优先关闭确认弹窗。
- 所有操作均有可见焦点和准确的无障碍名称。

## 8. 迷你计时条

退出沉浸模式且仍有活动会话时，在主内容区底部固定显示迷你计时条。它包含主题、时间、状态、暂停/继续按钮和重新进入沉浸模式按钮。

迷你条不会遮挡列表末尾内容；主内容区需增加等量底部安全间距。移动端使用单行紧凑布局，超长主题省略但保留完整 `title` 或可访问名称。

处于 `focus-complete` 或 `break-complete` 时，迷你条改为结果提示，并提供返回沉浸界面处理下一步的按钮。

## 9. 休息阶段

番茄完成后立即保存专注记录、播放提示音并显示完成结果，不自动开始休息。用户点击“开始休息”后才进入休息倒计时。

休息可以暂停、继续或跳过。休息时长不进入专注统计，不生成历史记录，也不自动启动下一轮专注。休息完成后播放同一类短提示音并等待用户返回任务。

自由计时结束后不提供休息阶段。

## 10. 专注统计页

专注统计独立于现有任务统计页，按用户当前设置时区计算日期边界。

页面包括：

- 今日专注时长：今日结束的记录 `focusedMs` 总和。
- 今日完成轮次：今日 `mode: pomodoro` 且 `outcome: completed` 的记录数量。
- 本周专注时长：以周一为起点的本地自然周总时长。
- 最近七天柱状图：按记录 `endedAt` 转换到用户时区后分组。
- 主题分布：按 `taskId` 分组；无任务记录按 `subjectSnapshot` 分组。任务历史标题使用记录快照，不依赖当前任务是否存在。
- 最近记录：按 `endedAt` 倒序，显示主题、模式、实际时长、结束时间和完成/提前结束状态。

统计按毫秒聚合，展示时按最接近的整分钟显示；不足一分钟的记录显示“少于 1 分钟”，避免显示为零。最近记录保留秒级显示。

无历史数据时显示单一空状态和“开始专注”命令，不创建演示记录。

## 11. 提示音与反馈

提示音使用 Web Audio API 在用户已产生交互后播放简短、克制的双音提示，不引入音频资产或网络请求。浏览器拒绝或设备不支持播放时静默降级，记录保存和界面状态不受影响。

番茄完成、休息完成时各播放一次。页面恢复或重复渲染完成状态时不重复播放；播放触发与状态转换结果绑定。

## 12. 错误与边界处理

- 当前关联任务被删除：活动会话继续，使用 `subjectSnapshot`；统计历史不受影响。
- 当前关联任务被改名：活动会话和既有历史继续显示开始时快照；下一次从任务入口开始时使用新标题。
- 重复开始：打开既有活动会话，不创建第二条。
- 非法时长：阻止开始并显示允许范围。
- 空主题且无任务：阻止开始并提示输入主题。
- 系统时间向后跳：本次运行区间按不小于零计算；已累计时长不减少。
- 提示音失败：静默降级。
- 持久化数据缺字段或状态无效：保留可解析历史和设置，丢弃无法安全恢复的活动会话，并回到空闲状态。
- 提前结束确认期间计时继续；用户确认时以确认瞬间为结束时间，取消则继续原状态。

## 13. 响应式与无障碍

- 桌面和移动端均使用全视口专注层，不依赖浏览器 Fullscreen API，因此不会触发权限或退出提示。
- 计时数字使用稳定宽度数字和固定容器，秒数变化不引发布局抖动。
- 移动端控制按钮允许换行但不互相遮挡。
- 颜色不是唯一状态信号；每种状态都有文字与图标语义。
- 支持 `prefers-reduced-motion`，进度环仅更新数值，不使用持续旋转或呼吸动画。
- 设置弹窗和提前结束确认框遵循现有模态焦点管理：进入时聚焦、Tab 限制、Escape 和关闭后焦点恢复。

## 14. 测试策略

### 14.1 纯状态机测试

使用注入时钟，不等待真实时间：

- 番茄与自由计时的开始、暂停、继续。
- 时间戳计算不受更新频率影响。
- 番茄到点、提前结束和完成幂等。
- 手动开始、暂停、继续和跳过休息。
- 系统时间回退时累计时长不减少。

### 14.2 Store 与持久化测试

- 设置、活动会话和历史写入 `rixu-focus:v1`。
- 刷新后运行会话恢复为暂停，关闭期间不计时。
- 到点后页面隐藏只生成一次记录。
- 任务删除后活动会话和历史仍保留主题快照。
- 存在活动会话时拒绝创建第二条并返回现有会话。
- 损坏持久化数据按安全规则恢复。

### 14.3 统计测试

- 今日、本周、七天边界。
- 用户时区跨 UTC 日期和周边界。
- 番茄完成轮次只统计正常完成记录。
- 任务与临时主题分布。
- 不足一分钟展示规则。

### 14.4 React 集成测试

- 顶栏无任务入口与任务行关联入口。
- 模式切换、主题校验、时长范围和记住设置。
- 沉浸界面暂停、继续、提前结束确认和退出。
- 迷你计时条恢复沉浸界面。
- 番茄完成后手动开始休息。
- 键盘快捷键与模态焦点行为。
- 专注统计的有数据和空状态。

### 14.5 Playwright

- 桌面端使用可控短时长完成一轮番茄，验证只生成一条记录并可手动进入休息。
- 移动端开始自由计时、暂停、刷新，验证恢复为暂停且页面无横向溢出。
- 浏览器测试通过测试专用时钟或页面注入缩短时间，不真实等待一分钟。

## 15. 实施边界

- 只修改 `web/` 与相关前端文档，不修改根目录 `src/` 和 `tests/`。
- 复用现有 Zustand、Vitest、React Testing Library、Playwright、Lucide 和 CSS 体系。
- 专注统计不改变现有任务完成率、完成热力图或任务模型。
- 本期数据仅保存在当前浏览器，不宣称跨设备同步。

## 16. 验收标准

1. 用户可从顶栏开始临时主题专注，也可从任务行开始关联专注。
2. 番茄钟和自由计时均能开始、暂停、继续和提前结束。
3. 番茄正常到点只保存一条完成记录，并等待用户手动开始休息。
4. 提前结束保存实际时长且不修改任务完成状态。
5. 刷新后活动会话恢复为暂停，关闭期间不计时。
6. 退出沉浸模式后迷你计时条持续展示活动会话并可恢复。
7. 删除关联任务不影响活动会话或历史记录。
8. 专注统计准确展示今日、本周、七天、主题分布和最近记录。
9. 提示音失败不影响计时和记录。
10. 桌面、移动端、键盘与减少动态效果设置均可用。
11. 原任务领域测试、前端测试、生产构建和浏览器冒烟测试全部通过。
